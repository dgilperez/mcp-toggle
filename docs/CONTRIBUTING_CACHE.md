# Contributing to MCP Server Cache

The MCP server cache (`data/mcp-cache.json`) is automatically regenerated weekly via GitHub Actions. You can contribute by:

## 1. Adding Manual Metadata

Edit `data/manual-metadata.json` to add impact ratings and better descriptions for servers.

### Impact Categories

Estimate based on typical response size:

- **Heavy** (1000+ tokens): Servers that return large content
  - `filesystem`, `figma`, `puppeteer`, `obsidian`
  - Returns: Full file contents, design layers, HTML/DOM, markdown files

- **Medium** (100-1000 tokens): Moderate API responses
  - `github`, `postgres`, `sqlite`, `notion`, `pubmed`, `fetch`
  - Returns: API data, query results, pages, abstracts

- **Light** (<100 tokens): Compact responses
  - `brave-search`, `slack`, `memory`, `sequential-thinking`, `time`
  - Returns: Search snippets, messages, minimal state

### Example Manual Entry

```json
{
  "servers": {
    "your-server": {
      "description": "Clear, concise description of what it does",
      "impact": {
        "estimated_tokens": 500,
        "category": "Medium",
        "method": "manual",
        "measured_at": "2025-01-20"
      },
      "categories": ["database", "dev-tools"]
    }
  }
}
```

## 2. Measuring Impact with Claude Code

The most accurate way is to use the measurement script:

```bash
# Run locally (requires Claude Code installed)
./scripts/measure-impact.sh
```

This script will:
1. Open Claude Code in a new terminal
2. Guide you through running `/context`
3. Parse the MCP server token counts
4. Automatically update `data/mcp-cache.json` with real measurements
5. Change `"method": "manual"` → `"method": "measured"`

**Manual method** (if you prefer):
1. Start fresh Claude Code session
2. Enable the MCP server you want to measure
3. Use the `/context` command
4. Look for "MCP" section showing token usage per server
5. Add measurement to `data/manual-metadata.json`

Example:
```bash
# In Claude Code session
/context

# Output shows:
# MCP: 1,234 tokens
#   - filesystem: 1,200 tokens  <- This is what you want!
#   - brave-search: 34 tokens
```

## 3. Improving Cache Generation

The cache is generated by `scripts/generate-cache.sh` which:

1. Fetches from MCP official registry
2. Gets npm stats (downloads, versions)
3. Merges with manual metadata
4. Outputs to `data/mcp-cache.json`

To improve the script:
- Add more data sources
- Improve categorization logic
- Add validation checks
- Better error handling

## 4. Testing Your Changes

Before submitting a PR:

```bash
# Test cache generation
./scripts/generate-cache.sh

# Verify JSON is valid
jq . data/mcp-cache.json > /dev/null && echo "Valid JSON"

# Test the discover command
./mcp-toggle.sh discover

# Test metadata for specific server
./mcp-toggle.sh info your-server
```

## 5. Local Overrides

Users can create `~/.mcp/local-metadata.json` to:
- Override impact ratings
- Add custom servers
- Extend descriptions

Format is identical to `data/manual-metadata.json`:

```json
{
  "servers": {
    "my-custom-server": {
      "description": "My custom MCP server",
      "impact": {
        "estimated_tokens": 300,
        "category": "Medium",
        "method": "manual",
        "measured_at": "2025-01-20"
      }
    }
  }
}
```

## Submitting Changes

1. Fork the repository
2. Edit `data/manual-metadata.json`
3. Test with `./scripts/generate-cache.sh`
4. Create PR with:
   - Description of what you added/changed
   - How you measured impact (if applicable)
   - Any supporting screenshots from `/context`
